PikPak 分享恢复指定目录修复设计

日期：2026-08-01 · 状态：用户已确认设计方向，待书面规格复核

本规格取代同日基于 to_parent_id 或 to.parent_id 的旧恢复目标设计。

目标与边界

将用户勾选的 PikPak 分享文件恢复到程序为本次请求创建的唯一隔离目录，并且只从该目录获取本次恢复产生的文件。禁止使用或递归展开根目录下复用的 Pack From Shared。

唯一成功标准：恢复任务中的源文件 ID 集合、目标文件 ID 集合和隔离目录直属文件集合完全对应，数量与用户勾选项一致，且没有任何额外文件。

本次不改变分享列表解析、文件命名、TelDrive 路径、串行下载模式和 aria2 推送方式；只修复恢复目标协议及其验证流程。

已确认根因

当前实现发送嵌套字段 to.parent_id。PikPak 接受请求但静默忽略该字段，随后把响应 file_id 指向根目录下既有的 Pack From Shared，新建隔离目录保持为空。

服务器实测证明，当前接受的指定目录协议是顶层 parent_id，并同时设置 specify_parent_id: true。任务跟踪还需要 ancestor_ids 和 params.trace_file_ids。

恢复请求协议

{
  "parent_id": "本次新建隔离目录 ID",
  "share_id": "分享 ID",
  "pass_code_token": "分享访问令牌",
  "file_ids": ["用户勾选的分享文件 ID"],
  "ancestor_ids": [],
  "specify_parent_id": true,
  "params": {
    "trace_file_ids": "勾选文件 ID，多个以逗号连接"
  }
}

不得同时发送 to.parent_id 或 to_parent_id，也不得在指定目录失败后回退到普通 restore()。

数据流

用户勾选分享文件
  -> 创建唯一 .teldrive-share-<uuid> 隔离目录
  -> 使用 parent_id + specify_parent_id 提交恢复
  -> 校验响应 file_id == 隔离目录 ID
  -> 轮询 /drive/v1/tasks/{restore_task_id}
  -> 解析 params.trace_file_ids 的源 ID -> 目标 ID 映射
  -> 校验源 ID 集合 == 用户勾选 ID 集合
  -> 读取隔离目录直属文件
  -> 校验直属文件 ID 集合 == 映射目标 ID 集合
  -> 只为这些目标文件获取直链
  -> 全部通过后一次性进入 aria2/串行队列
  -> 结束后只清理本次隔离目录

组件职责

组件职责
app/modules/pikpak/client.py 创建隔离目录、构造指定目录请求、校验恢复响应、轮询任务、解析 ID 映射、读取直属文件并获取直链。
app/modules/pikpak/routes.py 传递用户勾选 ID 和原始路径清单；只有完整验证通过后才向 aria2 或串行队列提交；最终只清理客户端返回的自有隔离目录。
tests/test_pikpak_share_restore_isolation.py 覆盖请求载荷、响应目标、任务映射、目录成员、失败不推送和清理所有权。

校验与失败策略

  1. 创建目录没有返回 ID：立即失败，不调用恢复接口。
  2. 恢复响应 file_id 不等于隔离目录 ID：视为目标字段未生效，立即失败。
  3. 缺少 restore_task_id：除非响应已完成并提供可验证的完整映射，否则失败。
  4. 任务失败、超时或 trace_file_ids 无法解析：失败。
  5. 映射源 ID 与勾选 ID 不完全一致：失败。
  6. 隔离目录直属文件 ID 与映射目标 ID 不完全一致：失败。
  7. 任一目标文件没有可用直链：整批失败，不向 aria2 推送部分结果。
所有失败路径都必须保持 aria2 推送数量为 0。禁止扫描根目录、禁止使用返回的非自有目录、禁止按名称从其他目录补齐结果。

清理所有权

程序只记录并删除本次成功创建的隔离目录 ID。恢复响应中的其他 ID、任务 ID、Pack From Shared 及其子项均不属于清理范围。

即使请求、轮询或直链解析失败，也只能尝试删除该隔离目录。清理失败要记录日志，但不能扩大删除范围。

测试方案

自动化测试

  • 请求体包含顶层 parent_id、空 ancestor_ids、specify_parent_id: true 和逗号连接的跟踪 ID。
  • 请求体不包含 to 或 to_parent_id。
  • 响应目录不匹配、任务映射缺失/多余、目录成员缺失/多余时均推送 0 条链接。
  • 单文件和多文件成功时，只推送映射到隔离目录的目标文件。
  • 所有路径只清理本次隔离目录。

服务器验收

使用用户提供的分享链接分别执行单文件和双文件测试，不调用 aria2。要求响应目录、任务映射、直属文件数量、名称、大小和父目录全部一致。部署后再通过真实下载入口执行一次，确认 aria2 只收到勾选数量的链接。

已有实测证据

场景结果
旧 to.parent_id响应指向 Pack From Shared，隔离目录为空。
新协议，单选 4K响应指向隔离目录；目录只有 paid_4k.mp4，名称与大小一致。
新协议，同时选择 8K 与 4K任务映射恰好包含两个源 ID；隔离目录恰好有两个对应目标文件，无额外文件。

两次诊断目录均已删除，未调用 aria2，未删除或修改 Pack From Shared。

发布与回滚

  1. 先运行 PikPak 隔离恢复测试及相关测试集。
  2. 部署前备份服务器上的 client.py 和 routes.py。
  3. 部署后重启 teldrive-manager.service，检查服务状态和启动日志。
  4. 先执行不触发 aria2 的恢复探针，再通过程序真实入口完成端到端验证。
  5. 若验收失败，恢复本次部署前备份并重启服务；不删除任何用户网盘目录。
